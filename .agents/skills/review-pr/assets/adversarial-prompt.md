**送出時只送第一條 `---` 之後的內容**（本檔開頭到該線為止是填寫說明，不外送）。
外部 agent 在同一個 repo 的 cwd、唯讀環境：**給路徑與 ref，不貼 diff**；它看不到這個對話，背景要一段話講完。

要它做的不是「再 review 一次」，而是**換立場**：你已用檢查清單審過一輪，它要當攻擊者與時序對手，專找 diff 之外的證據來推翻作者的前提。

**攻擊者視角**：
- 外部呼叫端能控制哪些最終落入這段 code、設定或文件的值？有沒有驗證或 allowlist？能不能帶憑證、個資，或把格式弄壞？
- 遮罩或過濾若是 denylist，列出所有沒被列到、但實際會出現在資料裡的欄位路徑。

**時序對手視角**：
- 每個「先驗證、後動手」的序列（數量相符則略過、確認到尾端才刪除、先檢查存在再寫入）：驗證與動手之間有沒有窗口？窗口內誰可以寫入？鎖擋的是誰、沒擋誰？
- cursor、keyset、分頁：排序鍵是否真的唯一且全序？跨邊界會不會跳列或重複？斷言在跳列時會不會照樣通過？

**缺口被文件化的地方**：測試或註解出現「by design 會漏」「機率極低」「padding 足夠」這類措辭，洞被觸發時系統怎麼發現、怎麼補？沒有答案就列出來。
